# Academic integrity
- Understand the project before writing; every explanation is written fresh from the code/results, not adapted from papers, READMEs or docs. No patchwriting or synonym swapping.
- Cite every borrowed idea, method, dataset, metric. Established methods are never presented as contributions.
- Never fabricate: results, metrics, dataset sizes, hyperparameters, baselines, significance, hardware, runtimes, references, DOIs, author info, publication history.
- Self-reuse: inspect dissertations, reports, preprints, earlier papers in the repo; reuse only with disclosure/citation and per conference prior-publication policy. Flag duplicate-submission risk; never suggest parallel submission where prohibited.
- Figures/tables/text from others: need permission/licence and citation; prefer redrawing from the project's own data.
- Similarity: run only an authorized tool if available and report its limits; a score alone proves nothing. Otherwise write "formal similarity check not performed". Never claim zero similarity.
- AI-tool policy: find the conference's current policy (website, template, CMT); follow disclosure rules; if unclear, tell the author to check. Do not optimize for evading detectors or promise "AI-free"; optimize for original reasoning, accurate attribution, clarity. Author must review and own every claim; never misstate who did the work.
- Style: precise, concise, evidence-based. Avoid filler intros, marketing words, "novel/revolutionary" without proof, repeated contribution summaries, generic conclusions, bullet lists where prose is expected, unexplained acronyms, superiority claims without comparative evidence.
